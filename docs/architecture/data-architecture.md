# Data architecture

## Ownership and access

One PostgreSQL database/user per service; local server sharing is operational only. Schemas/private persistence cannot be read by another owner. READ COMMITTED default, UUID primary keys, UTC timestamptz, FK within owner, explicit named check constraints. Money BIGINT minor units+currency. Flyway migrations immutable after release. Row version used for updates. Short `FOR UPDATE` account/subscription locks serialize count/state invariants; external calls never occur while holding locks.

Multi-AZ synchronous HA for PostgreSQL writes. Read replicas only for stale-tolerant browse/reporting, never payment/concurrency authorization. Partition audit/history monthly after measured volume. Partition/shard transactional accounts only with a new measured-access-pattern ADR. Pool sum across replicas must remain below DB connection reserve. Daily encrypted backups + continuous WAL/PITR; quarterly restore drills. See DR for RPO/RTO. Erasure removes owner PII and tombstones projection IDs; financial/legal holds explicitly documented, not assumed compliance.

## Redis policy

| Use | Key / TTL | Authority / invalidation | Miss / stampede | Failure |
|---|---|---|---|---|
| Entitlement | ent:{account}:v; positive 15s, negative 3s, bounded by actual expiry | commerce; change event evicts; signed decision expiry remains hard bound | owner REST; singleflight with jitter, no stale allow | fail closed if authority unavailable |
| Concurrent streams | lease:{account} ZSET session→expiry, TTL 180s; max 90s active | playback durable session/grant ledger; Lua removes expired, compares count, inserts atomically | durable slot reservation before Lua; ended grants keep capacity until expiry | fail closed on missing lease; PostgreSQL ledger prevents Redis loss overbooking; stale DB restore requires writer fencing/quarantine (unexercised) |
| Rate limit | rl:{subject}:{route}:{window}, TTL window+5s | deliberately ephemeral security counters | atomic INCR/Lua | gateway safety cap; reject abuse-prone mutations if enforcement unavailable |
| Catalog | cat:{id}:{locale}:{version}, 300s | content; immutable version; publish evicts aliases | owner/read replica; jitter and singleflight | browse owner fallback; rights never inferred |
| Trending | trend:{country}:{maturity}:{window}, 60s | experience aggregate | popular deterministic fallback | omit optional rail |
| Ad cap | adcap:{account}:{campaign}:{window}, max window end | engagement DB authoritative | CAS owner DB; no speculative cache allowance | skip optional ad |

No Redis cache is an accidental business authority. Lease coordination is intentionally ephemeral coordination, constrained by durable grant expiry/fencing. Event invalidation is optimization, not the only revocation safety boundary.

## NoSQL evolution (not initially deployed)

DynamoDB watch-state candidate only after measured PG saturation: PK `PROFILE#id`, SK `CONTENT#id`; query per content and paged recent via GSI partition profile+month; estimated 100M active rows; conditional version writes, strongly consistent resume reads; TTL 180d history, progress policy separate; hot profile bounded by request rate limits. Playback history candidate PK `ACCOUNT#id#day`, SK `START#instant#session`; eventual history reads; 30d TTL; hot live events avoided because partition key is account, not content. These are alternatives, not current runtime dependencies.

Rights API timestamps must align to PostgreSQL microsecond precision; evaluators floor current time to microseconds before SQL comparison so JDBC rounding cannot prematurely cross an inclusive start boundary. Sub-microsecond grant timestamps are rejected explicitly.

## Phase 6 implementation alignment

Experience owns PostgreSQL progress, profile bindings, inbox/session sequences, history, watchlists and reaction tombstones. Playback owns the shared online/offline account epoch counter and validates grants over scoped REST. Per-profile/content locks, event UUID hashes and sequence checks preserve local ACID writes; outbox aggregate versions are per profile/content row and Kafka keys are profile IDs. Ratings specify 1–5 stars or 0 for no star rating in the first v1 producer; nullable thumb/removal fields retain Avro defaults. See [ADR-018](../adr/ADR-018-watch-state-ordering.md) for ordering, legacy migration, pagination, client-duration trust and retention constraints. No measured NoSQL need or production retention/DR validation is claimed.

## Phase 7 implementation alignment

Content owns draft taxonomy and immutable exact-version localized published snapshots. Experience consumes catalog.published.v1 through bounded retries/DLQ, hydrates those scoped owner snapshots, and commits its PostgreSQL search projection/inbox. Its separate claimed index worker uses per-content/locale OpenSearch external versions; stale acknowledgements cannot mark a newer projection complete. Search/home validate profile ownership and batch-filter through current Content rights/maturity before returning metadata. Search failure returns unavailable; home can use durable recent metadata under the same policy. A scoped rebuild intent pages owner snapshots and reconstructs a lost index. Experience workload scopes now include content.internal plus playback.internal. See [ADR-019](../adr/ADR-019-search-projection.md) for query bounds, country semantics, index-loss versus regional DR, locale/analyzer limits, production TLS/credentials and replication.

## Phase 8 implementation alignment

Experience builds deterministic recent-release, genre/actor and consented history rails from durable catalog metadata. Popular/trending consume validated playback.started.v1 records, cap one profile/content/day and default to no profile contribution before opt-in. Derived daily counters and event hashes commit together; preference row locks serialize starts with opt-out erasure and a default 200-content daily cap. 90-day retention runs in bounded batches. Source time and enabled-since prevent retroactive pre-consent imports. All seeds/candidates use current rights/maturity; no signal/index call is a synchronous Playback dependency. Response basis distinguishes actual opt-in starts from recent fallback, and personalized=true requires a nonempty applied history rail. See [ADR-020](../adr/ADR-020-recommendation-signals.md). Counts are opted-in heuristics, not total audience, fraud-proof engagement, billable viewing or measured recommendation quality.

Phase 9 live control: Content V4 owns live_event/content relation (one event per sports content), ordered schedule index, optimistic state version, monotonic source epoch/sequence, idempotent command receipts, audit and bounded highlight references. Signed heartbeat receipts do not emit a lifecycle event; transitions/reschedule/failover/highlights do so atomically. Playback V5 adds event/mode targets and preserves existing VOD fingerprints; live and VOD share one durable account capacity ledger and Redis lease set. No shared database or new synchronous Playback→Engagement dependency. See ADR-021.

Phase 10 advertising uses Engagement V1: bounded versioned campaign configuration and hashed actor audit; account lock rows; decision reservations indexed by account/campaign/UTC reservation day/state; unique account/idempotency key; receipt UUID/hash deduplication; unique decision/quartile measurement; typed outbox. Issued opportunities count for the day even after expiry and absent reports. Pending-only reservations can be released before issue. Provider calls happen outside local transactions; claim tokens fence competing activation. Region derives from scoped Playback ad context, never untrusted client targeting input. A separate ad-context API preserves the existing generic/offline Playback context contract.

Phase 11 Engagement V2 owns account/channel consent and encrypted routing, bounded reminder requests, source UUID/hash receipts, versioned live state/last-source-time, unique account/template/cause/channel intents, expiring dispatch claims and owned keyset inbox. Source requests activate saved QUEUED intents via Kafka; they cannot invent recipients. Local in-app delivery/outbox is ACID. External calls occur outside locks; unknown non-idempotent outcomes reconcile. Pending opt-out/expiry cancellation and bounded fresh-live/content/expired-reminder sweeps preserve failure behavior. No raw contact/token in events. Contact encryption is owner-local AES-GCM with account/channel AAD; production KMS/rotation is a target integration.

## Phase 12 Insights ownership

`db/insights/V1` owns consent, telemetry receipts/detail, daily quotas, owner semantic causes, experiments/assignments/audit and outbox. Account row locks serialize concurrent consent/admission and quota decisions at READ COMMITTED. Event UUID/hash and unique session/sequence reject collisions; owner cause `(kind,cause)` ignores semantic duplicates. Reports carry interval deltas, not cumulative counters. Search/pre-grant failure has no fabricated session; only current grant-bound samples produce QoE session events. Client dimensions are untrusted coarse hints. Client payment/purchase/ad kinds are rejected; typed owner records establish business provenance. Old ad records without nullable accountId are deliberately ignored.

Indexes support account/time detail, time retention, receipt retention and pending outbox. Raw rows, admission receipts, owner causes and published outbox are retained30d with bounded1000-row cleanup/hour; quota cleanup is bounded. Cleanup lag remains observable operational work; table partitioning/archival is target evolution. Unpublished outbox is retained for recovery. Kafka telemetry retention is3d QoE/7d analytical; old business source retention30d remains independent. Opt-out removes local detail, semantic causes, pending analytics/QoE outbox and assignments, and reenabling creates a new server consent boundary. Receipt fingerprints remain for replay detection through30d. Published/in-flight Kafka records cannot be recalled by deleting SQL; downstream erasure/tombstones and cloud archive erasure are Phase13/15 work, explicitly not a complete privacy-erasure guarantee.

Experiment feature allowlist excludes all authorization controls. Versioned assignment uses a distinct32-byte HMAC key; telemetry pseudonyms use a separate32-byte key. Missing privacy key causes admission rollback/503; missing assignment key returns CONTROL. Rotating keys requires an epoch/migration procedure and reidentification/erasure strategy; replacing them ad hoc is not an established production rotation protocol.

## Phase13 security and activity retention

Member V4/V5 adds salted adaptive PIN, persistent lockout/cooldown, hashed opaque profile/device/revision/version selection grants, account status/security epoch and idempotent owner security receipt/audit. Configured adult selection and maturity escalation require parent credentials; unconfigured accounts preserve compatibility and explicitly report disabled selection locking. Recent trusted OIDC authentication plus existing PIN is required to change/disable it; no unsafe recovery route is supplied. Failed checks commit independently before throwing. Successful authorization/configuration fences the checked PIN revision. Account/profile/device security changes invalidate old offline epoch snapshots.

Commerce V2/V3 owns cancellation and administrative revocation/restore receipts/audit. Immediate cancellation requires resolving an open purchase; later access requires a new verified paid order. Administrative access_revoked remains true while a pending payment settles; its invoice is recorded without enabling access. Restore is explicit. Subscription changeReason is additive/defaulted PURCHASED; security restore events are not new purchase analytics. No refund/provider money movement is inferred by access cancellation/revocation. Paid invoices retain financial evidence pending an authoritative retention/refund policy.

Playback V6 records Member security epoch in offline grants. Current license checks verify active member/profile/device and unchanged epoch, current rights/origin/offline allowance and active entitlement through bounded scoped owners. Existing grants with legacy epoch0 require fresh authorization. A content becoming live-associated also denies earlier ordinary offline credentials. Disconnected commercial DRM revocation and delivered mock-clear bytes remain unvalidated provider/client boundaries. Already issued online CDN signatures remain bounded by their existing≤60s expiry.

Operations V1/V2 owns receipt/provenance/window indexes, deterministic rule cases, versioned support requests, fenced idempotent owner commands and append-only audit/outbox. UUID collisions and quota/CAS failures do not partially create a case/action. Signal source_ref hashes the authenticated integration principal/source; no raw credentials are stored. Confidence0 means no calibrated statistical confidence, even where a deterministic threshold opens a case. Rule flags are indicators for human review, not evidence of fraud.

Experience V4 retention removes watch detail/history/receipts/session sequence after180d in bounded1000-row batches. Explicit watchlist/reaction preferences persist until user removal; recommendation signals already have90d retention/default-off consent. Engagement V3 removes completed notice/inbox and settled ad observation detail/receipts after30d; pending/unknown RECONCILE/DISPATCHING intents and verified contact preferences are retained for explicit resolution/configuration removal. Unpublished outboxes and privileged audit/financial evidence require controlled recovery/retention, never silent deletion. This is local minimization/retention, not a complete cross-owner/Kafka/backups/cloud/legal erasure guarantee.
