# Playback control plane and DRM

Playback initially resolves account through member with the viewer JWT, checks member(device/profile), then checks commerce(entitlement) and content(rights/version/availability) in parallel with a cached client-credentials workload JWT. The rights request requires verified profile maturity, so that dependency follows member validation. Trusted edge country is required; public country headers discarded. Inputs bind account/profile/device/content/format, supported codecs/DRM and geo. Maturity and territorial `[start,end)` windows checked; DRM/offline policy uses the same eligibility.

Target production budget remains 300ms p95. The initial implementation uses connect100ms/read300ms per owner, a 40-request owner-check bulkhead, virtual threads for the two parallel checks, and connect300ms/read700ms for workload-token acquisition. No retries in authorization. Cold identity resolution/token acquisition can exceed the target; latency/load validation and safe identity-cache optimization remain phase15 work. No measured latency SLO claim. No synchronous recommendations, analytics, experiments or notifications.

Lease acquisition Lua uses Redis TIME (not client clocks), same `{account}` hash slot, purges expired entries, counts active, enforces cap, returns idempotent existing session or atomically reserves new one. Lease90s, heartbeat30s, grants≤60s. A DB session/grant ledger is authoritative for capacity and issued grants. First reserve a slot in a short per-account quota-row transaction, counting all unexpired pending/active slots. Then acquire the Redis lease outside that transaction, and finally conditionally activate/sign the reserved session. Redis failure cancels only an unissued reservation; an ambiguous/crashed reservation remains counted until expiry. This local reservation + compensation avoids cross-store 2PC and ensures Redis data loss cannot overbook valid grants. Heartbeat extends the durable slot before Redis renewal; signing follows only confirmed renewal. Redis loss may deny an existing heartbeat; it cannot remove durable occupied slots. Ended sessions retain capacity until their last grant expiry. New grants count pending/active and still-valid ended slots under the quota lock. No Redis epoch needed while this ledger is current. PostgreSQL restore requires writer fencing and a60s issuance quarantine before rebuilding capacity; this runbook is unexercised. Multi-writer regions prohibited. Account plan limits cannot be raised from untrusted input.

Crash matrix: before DB reserve no change; after DB reserve/before acquire pending slot safely expires; after durable reservation/before signing no grant and lease released on reconciliation; after signing/response loss record bounded grant and return only on matching idempotency key; after Redis loss retain ledger and deny lost-lease heartbeat. Release/heartbeat require session owner+device, never revive expired or revoked sessions. Durable expiration cleanup tolerates duplicate jobs.

Target production tokens use asymmetric keys/workload verification and commercial device proof. Initial local grants use HMAC-SHA256, separate aud=ott-playback/ott-offline, jti, account/profile/device/session/content, and expiry. Internal workload-protected validators require signature, audience, expiry, device, durable active session/download and exact token hash in the audit. Only hashes persisted. Secrets supplied externally; not committed. Local device ID binding alone is not cryptographic hardware proof. Bound max TTL to earliest rights/subscription expiry. Replay limited by short TTL/device-bound DRM proof; signed CDN cookies alone are bearer credentials and cannot fully prevent replay. DRM client cryptographic binding/commercial anti-piracy and watermarking are later launch measures, not claimed solved by JWT.

CDN: CloudFront signed cookies scoped to immutable content/version prefix protect manifests AND relative segments; S3 blocks public access and permits CloudFront OAC only. Local signer returns explicit local authorization, never pretends CloudFront accepts it. Production RSA signer/key group in Secrets Manager/KMS boundary; secure HttpOnly/SameSite cookie delivery where clients support cookies; URL mode requires segment authorization strategy.

DRM port supports Widevine/FairPlay/PlayReady through external provider. MockDrmProvider local only, no actual production protection. Business DB stores key IDs/license metadata, never content keys. Key exchange handled by packager/provider KMS/HSM. License endpoint checks active session, plan, device, geo, expiry; audit decision without license bytes/secrets. Offline grants track device limits, expire within download rights/plan; commercial renewal governs revocation latency.


Initial offline authorization uses the same owner/geo validation and both plan+rights offline flags. Per-account configured active-download limit5, idempotency fingerprint, device-bound audience, owner revoke and durable token hashes. License metadata expires within24h and rights/subscription windows; delivery cookies expire within60s. No real offline DRM license is issued. Commercial offline revocation latency follows provider/device license policy; a signed CDN cookie remains usable until its60s expiry even after local revoke.

`CloudFrontCookieSigner` signs exact immutable prefix wildcard custom policies using RSA2048+/SHA256 and the CloudFront-Hash-Algorithm cookie, protecting relative segment paths when deployed to a configured trusted key group. Format follows [AWS signed-cookie documentation](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-setting-signed-cookie-custom-policy.html). Cryptographic policy/signature verified locally; actual CloudFront acceptance not executed. Local MockDrmProvider creates an ephemeral untrusted signing key and declares MOCK_CLEAR_ONLY at local-cdn.invalid; no production protection or delivered media claimed. Prod profile excludes this adapter and requires a real GrantProvider.
