# Event architecture

Kafka integration delivery is at least once. PostgreSQL transactional outbox is written with owner state. Relay holds per-aggregate ordering through owner version; downstream uses version guards because retries/multiple relays can reorder. Producer key is the aggregate key below, not global order. Idempotent producer+acks=all does not make DB+Kafka exactly once.

Avro schemas under `contracts/events`; Schema Registry subject `{topic}-value`, BACKWARD_TRANSITIVE, register in CI before producers. Envelope: eventId UUID, type, aggregateId, aggregateVersion long, occurredAt UTC millis, producer, traceId, typed payload fields per event. No PII/credentials in envelope. Every planned topic has a typed Avro record registered in topics.json; envelope.avsc is a tooling example only and is not a business topic value schema. Semantic changes require compatibility review in addition to registry checks.

All topics: owner publishes, consumers above have independent groups. Initial 12 partitions for business integrations, 48 for telemetry as capacity assumptions; replication 3/minISR2 in production; local broker replication1 only. Retention is not legal archive retention. Max message256KiB (media URLs/reference only, never bytes). Schema specified by event type under Avro v1; topic registry inventory generated in contracts/events/topics.json.

Retry: transient consumer error → up to5 exponential jittered attempts (100ms–5s), bounded total deadline, then retry topic; poison payload→DLQ immediately with eventID/reason and redacted body. DLQ ownership belongs to consuming owner. Recovery requires corrected schema/handler and audited replay. Do not block a partition indefinitely. Kafka outage grows bounded outbox; admission shedding at age/size threshold preserves DB.

Inbox UNIQUE(consumer,eventId) committed with local side effects; index consumer uses external content version and a processed-ID record after confirmed write. Replay cannot charge money, resend notifications, activate expired entitlement or regress rights. Side-effect replay requires explicit suppression mode. Outbox pruning only after publication confirmation+retention; inbox dedupe window at least allowed replay horizon, older replay requires offline isolated rebuild. PII erasure tombstones affect projections and retained archives per legal review.

Producers use the packaged raw `.avsc` writer schema for Schema Registry exact lookup and binary serialization. Java generator annotations (such as avro.java.string) belong to readers and must not silently change registered schema identity.

## Phase 6 implementation alignment

Experience owns PostgreSQL progress, profile bindings, inbox/session sequences, history, watchlists and reaction tombstones. Playback owns the shared online/offline account epoch counter and validates grants over scoped REST. Per-profile/content locks, event UUID hashes and sequence checks preserve local ACID writes; outbox aggregate versions are per profile/content row and Kafka keys are profile IDs. Ratings specify 1–5 stars or 0 for no star rating in the first v1 producer; nullable thumb/removal fields retain Avro defaults. See [ADR-018](../adr/ADR-018-watch-state-ordering.md) for ordering, legacy migration, pagination, client-duration trust and retention constraints. No measured NoSQL need or production retention/DR validation is claimed.

## Phase 7 implementation alignment

Content owns draft taxonomy and immutable exact-version localized published snapshots. Experience consumes catalog.published.v1 through bounded retries/DLQ, hydrates those scoped owner snapshots, and commits its PostgreSQL search projection/inbox. Its separate claimed index worker uses per-content/locale OpenSearch external versions; stale acknowledgements cannot mark a newer projection complete. Search/home validate profile ownership and batch-filter through current Content rights/maturity before returning metadata. Search failure returns unavailable; home can use durable recent metadata under the same policy. A scoped rebuild intent pages owner snapshots and reconstructs a lost index. Experience workload scopes now include content.internal plus playback.internal. See [ADR-019](../adr/ADR-019-search-projection.md) for query bounds, country semantics, index-loss versus regional DR, locale/analyzer limits, production TLS/credentials and replication.

## Phase 8 implementation alignment

Experience builds deterministic recent-release, genre/actor and consented history rails from durable catalog metadata. Popular/trending consume validated playback.started.v1 records, cap one profile/content/day and default to no profile contribution before opt-in. Derived daily counters and event hashes commit together; preference row locks serialize starts with opt-out erasure and a default 200-content daily cap. 90-day retention runs in bounded batches. Source time and enabled-since prevent retroactive pre-consent imports. All seeds/candidates use current rights/maturity; no signal/index call is a synchronous Playback dependency. Response basis distinguishes actual opt-in starts from recent fallback, and personalized=true requires a nonempty applied history rail. See [ADR-020](../adr/ADR-020-recommendation-signals.md). Counts are opted-in heuristics, not total audience, fraud-proof engagement, billable viewing or measured recommendation quality.

Phase 10 ad.impression.v1 is produced by Engagement after validated client observation. Key/aggregate is decisionId; aggregateVersion increments on newly accepted semantic events under decision row locking. quartile 0 is an impression, 1–4 are independently reported quartiles. UUID/hash replay and unique decision/quartile protect duplicates; source claims are not proof of billable viewing. Existing 7-day activity retention/PII policy applies; privacy erasure and retention execution are later hardening work. The raw checked-in Avro writer is used for Registry wire serialization.

Phase 11 notification source semantics: Commerce payment.failed key and aggregate are accountId, version is Commerce account version, orderId remains the semantic notification cause. Content live.changed key/aggregate live event and version guard lifecycle; five-minute freshness bounds start fan-out. Owner notification.requested/delivered key account, aggregate intent, version 1/2. Requested consumer validates existing intent account/template before activation. Worker idempotency/fencing and intent uniqueness prevent replayed sends; unknown non-idempotent outcomes require explicit reconciliation. Raw invalid/exhausted messages park in topic DLQs. Delivery event represents durable in-app insertion/provider acceptance, not recipient read.

Phase12 publishes analytics.received.v1 (Insights; account UUID partition key/order boundary; owner monotonic version; Avro BACKWARD_TRANSITIVE;7d; restricted pseudonymous activity) and qoe.received.v1 (session UUID/sample sequence;3d). Ordering is partition arrival, not sample-sequence sorted order: consumers accept independent out-of-order interval samples and deduplicate eventId. Admission/outbox is atomic, relay at-least-once, bounded retry/backoff; producer publish failures remain pending. Analytical archive consumers are target architecture rather than a running S3 pipeline. Envelope UUIDs/sessionId are restricted linkable metadata despite HMAC payload references.

QoE kind/coarse dimension defaults and ad.impression nullable default accountId are additive to prior v1 writers. The journey registers previous schemas then current schemas under BACKWARD_TRANSITIVE in a real Registry and decodes actual messages. Insights owner consumers validate Registry writer identity, producer, key/aggregate, version and UUIDs; malformed/poison records use existing bounded retries/raw DLQs, never reinterpret client business claims. Source receipts and semantic causes avoid replay inflation; pre-consent/stale records are ignored. Ad quartile0 contributes AD_IMPRESSION; quartiles1–4 do not duplicate it. Consumer ACLs must permit only owner producers; producer text alone is not a cryptographic origin guarantee.

Phase13 first abuse.signal.v1 producer is Operations, with restricted trusted-source rule cases independent of analytics consent. Signal/action/audit Kafka key and aggregate are account UUID; monotonic Operations account counter is ordering/version boundary. Existing Avro BACKWARD_TRANSITIVE schemas,30d restricted retention, bounded relay retry/backoff and eventId dedup/replay apply; replay cannot automatically execute a punitive action. Command action events publish only after an owner receipt is recorded APPLIED; audits separately record QUEUED/RETRY/REJECTED/RECONCILE states. Confidence0 explicitly means no calibrated abuse probability. Payment source validates Commerce framing/type/producer/key/aggregate/version and UUIDs; poison/exhausted messages park in existing payment DLQ.

Subscription changeReason defaults to PURCHASED for old writers and records ACCESS_REVOKED/SECURITY_RESTORED for administrative changes. Insights ignores security restoration as a purchase. Topic ACLs give Operations producer authority for its three topics and consumer authority for payment failures. Commercial IdP/edge denial integrations require security.ingest and remain distinct trusted integration boundaries. The local signed-signal API is exercised with fixtures, not a real commercial detector.
