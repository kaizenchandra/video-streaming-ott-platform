# ADR-016: Authenticated purchase account resolution

Status: Accepted engineering update,2026-10-08.

## Context

FR-001/008..011; purchase must bind the member owner's generated account ID without accepting caller-supplied IDs or cross-database reads. Member currently provisions IDs from issuer+subject, not an IdP claim.

## Decision

Commerce viewer purchase/order/subscription APIs call member GET accounts/me with the validated caller token and bounded deadlines. Internal entitlement reads accept only trusted workload-scoped account IDs and never call member, keeping playback fan-out shallow. Extend commerce→member dependency map.

## Alternatives

Trust body accountId; private DB join; add account-created projection before needed; change token issuer to platform.

## Rationale

Authoritative owner resolution preserves security and existing IdP ownership with one bounded call on non-playback commands.

## Consequences

Member outage prevents new purchases/viewer order queries (safe503); internal cached/authoritative entitlement reads remain independent. Prepaid same-plan renewals supported; mid-period plan changes rejected until proration policy is configured.

## Operational Impact

Member connect300ms/read1s; no retry amplification; redacted errors. Payment provider calls remain outside DB transaction. Unknown outcomes pending reconciliation; no blind charge retry.
