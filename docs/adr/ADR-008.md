# ADR-008: Playback concurrency control

Status: Accepted technical baseline under autonomous task authority, 2026-10-08. Not external approval.

## Context

FR-012..014,027; NFR-001,004,005. Greenfield repository; workload targets are assumptions.

## Decision

Durable per-account capacity reservation under short local lock, then atomic Redis lease outside transaction, conditional grant activation, and conservative retention of outstanding grant capacity.

## Alternatives

Redis only; DB-only global lock.

## Rationale

Fast coordination must account for acknowledged-write loss and valid outstanding grants.

## Consequences

Deny uncertain store/fence state; grantTTL≤60s, lease90s.

## Operational Impact

Redis data-loss tests prove the durable ledger retains existing grant capacity. Redis recovery does not require an epoch for the initial single-writer design: every new grant still requires the PostgreSQL quota reservation. PostgreSQL restore/failover must fence old writers and quarantine issuance for at least the maximum grant lifetime before permitting a potentially stale restored ledger. These regional/database operations remain unexecuted. Redis-only concurrency is prohibited.
