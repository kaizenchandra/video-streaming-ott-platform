# Recovery runbook and evidence boundaries

## Repeatable local drill

Run `./scripts/mvn.sh --batch-mode -Pintegration,recovery,sbom verify` with Java21, a working Docker endpoint and the native media worker dependencies described in the README. The integration journey creates synthetic state in independent owner databases and disposable infrastructure. No real account/cloud backup is read or modified. All fixtures are cleaned after execution; ignored `tests/journey/target/recovery-evidence` retains the archives and measured summary for inspection. The directory is0700, SQL/media/event/schema archives0600. Use encrypted access-controlled storage for real backups; local synthetic files are not a production backup policy.

The recovery extension executes after the actual nine-owner journey:

1. Stop application writers/listeners. This is an explicit quiesced fixture, not a distributed live snapshot or 2PC protocol.
2. `pg_dump --no-owner --no-acl` all nine owner databases and restore actual archive files into separate new databases on an isolated PostgreSQL host. Compare all table row counts/content fingerprints, Flyway history, index key/uniqueness/validity metadata and partial-predicate row membership. Retain source/restored index definitions because PostgreSQL can rewrite equivalent casts. Confirm an ordinary mutation still fails the Operations immutable-audit trigger. Production role/grant restoration is separate because the local archive deliberately omits ACLs.
3. Discard only the disposable fixture's Redis cache. Confirm its restored authoritative PostgreSQL session/offline/quota ledger is unchanged; PlaybackIT separately exercises cache loss/timeout without quota overbooking. Never run this test's FLUSHDB against shared/local production caches.
4. Archive each real synthetic origin object and restore bytes into a separate empty S3 emulator bucket. Compare every object checksum, content type, cache policy and metadata. This does not exercise production KMS, cross-region replication, object versions or CDN switching.
5. Archive actual business-topic partition/key/value records and Registry subject versions/IDs. Import versions into a fresh Registry in IMPORT mode, restore BACKWARD_TRANSITIVE compatibility and return to READWRITE. Recreate same topic partition counts on a fresh broker, publish archived records and read back every key/value/partition. Decode actual Avro wire records through imported Registry IDs. The local broker uses replication1; MSK replication3/AZ failure is outside this test.
6. Delete the disposable OpenSearch index. Start restored Content and Experience owners, run actual checkpointed scan/indexer, compare localized document count with owned snapshots and replay duplicate catalog events through the actual consumer. Restored inbox receipts prevent duplicate side effects. No real charges or external messages are replayed.
7. Save measured elapsed times/counts/checksums and explicit NOT RUN fields. Local durations are neither cloud RPO nor cloud RTO; the test has no writes after quiescence and no regional routing transition.

## Production incident procedure — unexecuted target

Declare incident and capture operator/audit timestamps. Fence old writers and playback issuers before route changes; restore owner snapshots/PITR plus the verified schema/secret/identity version. Preserve financial idempotency keys, provider receipts, subscription/invoice state, outbox/inbox IDs and security epochs. Restore owner grants separately under least privilege. Reconcile uncertain provider outcomes before permitting charges; suppress irreversible downstream side effects during event recovery. Restore Registry IDs before consuming archived Avro bytes, retain partition boundaries and verify inbox/version guards.

Restore private versioned media with KMS permissions and content checksums before changing origin/CDN routes. Rebuild derived indexes from authoritative publication snapshots, recover watch/device epochs and rebuild disposable caches. Revoke/fence old region grants; do not accept DNS failover as proof that financial/session writers cannot overlap. Persistent Temporal history, workflow versions and activity receipts must be restored and verified before resuming jobs. Validate synthetic complete business journeys, then admit traffic gradually while measuring success/lag and burn alerts. Failback requires catch-up, another fencing transition, payment reconciliation and fresh epoch validation.

[Multi-region design](../architecture/multi-region.md) contains proposed domain-specific RPO/RTO. AWS regional failover/failback, Multi-AZ failover, production PITR, MSK replication/offset migration, real KMS/IdP/Temporal-history recovery and client traffic cutover remain NOT RUN. They need configured isolated cloud environments, sanctioned backups, provider credentials and operational/cost policy; no billed environment was provisioned by this task.
