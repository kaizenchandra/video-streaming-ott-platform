# Deployment package

This package is reviewable configuration, not an executed AWS deployment. The complete local business journey is exercised in `tests/journey`; Helm and mocked Terraform checks do not establish cloud availability, Multi-AZ behavior or commercial readiness.

## Build and local packaging

Run `./scripts/mvn.sh -Pintegration,recovery,sbom verify`. Prefer `python3 scripts/build-images.py` and `python3 scripts/build-images.py worker` for isolated minimal build contexts. Alternatively build each owner with `docker build -f platform/images/Dockerfile --build-arg OWNER=member -t ott-member:local .` (replace the owner), and media workers with `docker build --platform linux/amd64 -f media/worker/Dockerfile -t ott-media-worker:local .`. Only executable jars/probe source/Dockerfiles enter the build context. The native FFmpeg worker build always targetslinux/amd64, matching its pinned native base; schedule it on amd64 nodes. Owner images default to the local engine platform; for the reference m7i EKS nodes build with `OTT_IMAGE_PLATFORM=linux/amd64 python3 scripts/build-images.py` and publish verified digests through the configured release pipeline. Local arm64 owner images are not claimed compatible with that cloud node group. Runtime UID10001, read-only root, capped tmpfs and dropped capabilities are enforced by the chart. The generic image has an actual Java HTTP readiness healthcheck; the worker also has a real Java Docker readiness healthcheck, enabled by its default command; worker management is private port8091, enabled in worker values. Worker images currently require linux/amd64 FFmpeg; ARM emulation checks functionality only.

Helm release name is `ott` and namespace `ott`; default URL references match that release. Local values explicitly select mocks. Existing per-owner Secrets must contain only that owner's DB credentials, workload client secret and required crypto/provider settings. Never copy `.local/compose.env` into a pod or shared Secret. Provide local IdP/Schema Registry/Kafka/owner URLs, storage/Temporal endpoints, and dependency namespace labels/CIDRs in a private overlay. Label dependency namespace `ott-dependencies=true` and ingress/monitoring namespaces as chart selectors require. NetworkPolicy-capable CNI and metrics-server are prerequisites. Default deny policy is defense in depth; service JWT scopes remain authoritative. The current chart allows OTT-to-OTT TCP8080; finer per-owner transport policy remains a production strengthening step.

`helm lint infrastructure/helm/ott`; `.local/verification-venv/bin/python scripts/deployment_check.py` verifies semantic guards/routes after `pip install PyYAML==6.0.2` in that ignored venv. It does not call a Kubernetes API. The ALB edge list is ordered by specificity and uses AWS controller wildcard path rules. It excludes internal/actuator endpoints, but role-controlled admin/support paths are included. Review controller version, ALB rule quota, admin access policy and route behavior on a real cluster. JWT scopes enforce support/admin separation. Geographic assertion/header trust must be implemented in the real edge before playback can use production geo claims.

## Migrations and application credentials

Production enables one pre-install/pre-upgrade/Argo PreSync Job per enabled owner. Its terminating `DatabaseMigration` entry point calls only that owner's Flyway locations; application Flyway is disabled. Existing migration Secret contains `MIGRATION_DB_URL`, `MIGRATION_DB_USER`, `MIGRATION_DB_PASSWORD`; application Secret contains `<OWNER>_DB_URL`, `<OWNER>_DB_USER`, `<OWNER>_DB_PASSWORD` for a different DML-only user. Pre-create Secrets before Helm hooks. Schema owner creates tables; grant application USAGE on schema, SELECT/INSERT/UPDATE/DELETE on tables and USAGE/SELECT on sequences, plus default privileges for future tables. Never grant schema CREATE, table ownership, migration-admin login, trigger disable or superuser to applications. A local container drill exercises this separation. Review SQL privileges against the actual supported owner queries. No shared-schema ownership or database reads across owners.

Migrations are forward-only; inspect compatibility before deployment. Wait for all jobs; failed migration prevents upgrade. A rolling back application image never reverts schema. Initial3 replicas,250m/512Mi requests,1CPU/1Gi limits are assumptions, not measured production sizing. HPA is opt-in; no consumer-lag KEDA threshold is invented. The worker scratch disk is capped2Gi; source/output limits must fit that budget.

## AWS foundation

`terraform -chdir=infrastructure/terraform/aws init -backend=false`; `validate`; `test` execute schema and two mocked security plans. Provider is pinned6.38.0 and lockfile committed. Mock tests never contact AWS. The foundation defines three-AZ private EKS1.35, three NAT gateways, private API access with explicit operator role, audit logging/encryption, IMDSv2 nodes, nine physically isolated Multi-AZ PostgreSQL17 instances with managed master Secrets/35-day backups/deletion protection, MSK3.9 TLS/SCRAM/three brokers, Redis7.1 three shards+replicas/TLS, three-zone authenticated encrypted OpenSearch2.19, private versioned encrypted S3 origins and HTTPS CloudFront OAC/trusted signing key group, ECR, least-scope owner Secret roles and a regional API WAF. These sizes are costly reference assumptions; review region capacity, broker/instance support and budget before planning a real deployment.

Provide AZs/region, operator/search-admin IAM roles, public CDN signing key, separately created MSK SCRAM Secrets and Redis auth token through an encrypted secret input mechanism. Redis token is sensitive but still enters Terraform state; use encrypted restricted remote S3 state with locking, versioning, KMS and access audit. Never commit tfvars/plan/state containing credentials. Configure the empty S3 backend before real apply. MSK Secrets must use the required AmazonMSK_ prefix/KMS policy, and owner topic/consumer ACLs must be provisioned; no-ACL default is deny. Spring Kafka settings must use SASL_SSL/SCRAM-SHA-512 with owner JAAS credentials, and Redis must use cluster nodes/auth/SSL. Configure Schema Registry TLS/auth separately; current raw-Avro clients require a private trusted Registry endpoint and production authentication integration remains an explicit gate.

Separate platform installation must provide Schema Registry, durable production Temporal, OIDC/PKCE IdP, Secrets Store CSI/External Secrets integration, owner DB roles, AWS Load Balancer Controller, network-policy CNI, telemetry/export backends, alerts and trusted geo edge. OpenSearch IAM master bootstrap creates restricted internal users; the Experience adapter supports HTTPS/basic auth. Node role cannot fetch owner Secrets; projected IRSA claims bind exact service accounts. Media storage permissions currently bind the media API role; a distinct worker role/Secret/quarantine-only intake policy needs production separation before enabling media. S3 origin lifecycle/replication/WAF access logging and immutable audit archival require approved retention/residency/cost policy.

The production values intentionally disable Commerce/Playback/Media/worker because commercial adapters are absent. Guard rejects enabling them, mutable image tags, missing TLS/regional API WAF/dependency CIDRs/workload roles and application/migration Secret reuse. Use release and namespace `ott` to match exact workload role claims. Supply a private overlay and digest images for the other six services; production profile applies TLS search guards. This is partial production packaging, not a deployable complete commercial OTT platform. Argo templates require real repo URL/release commit; create the `ott` namespace with Pod Security restricted enforcement separately. No automatic sync/apply is enabled and no existing cluster context is modified.
